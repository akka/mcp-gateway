# Implementation Plan: Okta SSO Authentication

**Branch**: `004-okta-sso` | **Date**: 2026-04-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/004-okta-sso/spec.md`

## Summary

Protect all application pages with an Okta OIDC SSO login. Unauthenticated requests redirect to a login screen where the user enters a `@example.com` email, gets redirected to Okta, and returns to the app with a server-side session. Sessions are stored in Key Value Entities and enforced by a shared abstract base class used by all HTTP endpoints. No new external libraries are added — token validation uses Okta's userinfo endpoint via the `java.net.http.HttpClient` already in the codebase.

## Technical Context

**Language/Version**: Java 21
**Primary Dependencies**: Akka SDK 3.4+, Jackson (already present), java.net.http.HttpClient (already present)
**Storage**: Key Value Entities for `UserSession` and `OidcPendingLogin`
**Testing**: Akka TestKit (`TestKitSupport`), `KeyValueEntityTestKit`, JUnit 5, AssertJ
**Target Platform**: JVM service (local dev + Akka platform)
**Project Type**: Web service
**Performance Goals**: Login round-trip under 5 seconds (excluding Okta auth time) per SC-002
**Constraints**: `HttpOnly` + `SameSite=Lax` session cookie; sessions expire after 8 hours
**Scale/Scope**: Internal tool — small number of concurrent `@example.com` users

## Component Design

### Domain Layer

**`UserSession`** (record)
```
fields: email, displayName, createdAt, expiresAt
methods: isExpired(), empty()
```

**`OidcPendingLogin`** (record)
```
fields: loginHint, expiresAt
methods: isExpired(), empty()
```

---

### Application Layer

**`UserSessionEntity`** (Key Value Entity, state = `UserSession`)
```
emptyState()  → UserSession.empty()
create(CreateCommand)   → Effect<Done>   — stores new session
getSession()            → ReadOnlyEffect<UserSession>
invalidate()            → Effect<Done>   — clears state to empty
```

**`OidcPendingLoginEntity`** (Key Value Entity, state = `OidcPendingLogin`)
```
emptyState()   → OidcPendingLogin.empty()
create(Create) → Effect<Done>            — stores pending login with 10-min expiry
get()          → ReadOnlyEffect<OidcPendingLogin>
delete()       → Effect<Done>            — removes after use
```

---

### API Layer

**`AbstractProtectedEndpoint`** (abstract, extends `AbstractHttpEndpoint`)
```
protected ComponentClient componentClient  — injected via constructor
protected UserSession requireSession()     — reads SESSION cookie, looks up entity,
                                             returns null if missing/expired
protected HttpResponse redirectToLogin()   — 302 → /login
protected HttpResponse redirectTo(String)  — generic 302
```

**`AuthEndpoint`** (extends `AbstractProtectedEndpoint`, `@HttpEndpoint("/")`)
```
GET  /login              → serve login.html (no auth check)
POST /auth/initiate      → validate @example.com email, create OidcPendingLogin,
                           redirect to Okta authorization URL
GET  /auth/callback      → validate state, exchange code, call userinfo,
                           create UserSession, set SESSION cookie, redirect /
GET  /auth/logout        → invalidate UserSession, clear cookie, redirect /login
```

Startup: `AuthEndpoint` constructor fetches `{OKTA_ISSUER_URL}/.well-known/openid-configuration`
and caches `authorizationEndpoint`, `tokenEndpoint`, `userinfoEndpoint`.

**`OAuthEndpoint`** (currently extends `AbstractHttpEndpoint` → change to `AbstractProtectedEndpoint`)
- Add `requireSession()` call at the start of every handler method.
- `GET /` (root / index) also needs auth; it will additionally display the logged-in user's name from the session.

**`ZohoDeskEndpoint`**, **`SalesforceEndpoint`**, **`GenericMcpEndpoint`**
- Change to extend `AbstractProtectedEndpoint`.
- Add `requireSession()` at the start of their handler methods.

---

### Static Resources

**`login.html`**
- Email input field + **Continue** button
- Client-side JS validates `@example.com` domain before form submission (inline error, no network call)
- Form POSTs to `POST /auth/initiate`
- Styled consistently with existing `index.html`

**`index.html`** (existing, modified)
- Add a header bar showing the logged-in user's email/name (fetched from a new `GET /auth/me` endpoint or embedded server-side)
- Add a **Logout** button linking to `GET /auth/logout`

> Implementation note: to avoid a second network call, `GET /` can return the session user info inline. The simplest approach is a dedicated `GET /auth/me` JSON endpoint that returns `{email, displayName}`, called by the index page's JavaScript alongside the existing MCP status calls.

## OIDC Flow Detail

```
POST /auth/initiate
  1. Validate email ends with @example.com (400 if not)
  2. Generate state = UUID.randomUUID()
  3. Create OidcPendingLoginEntity[state] with loginHint=email, expiresAt=now+10min
  4. Redirect 302 to:
       {authorizationEndpoint}
         ?response_type=code
         &client_id={OKTA_CLIENT_ID}
         &redirect_uri={OKTA_REDIRECT_URI}
         &scope=openid profile email
         &state={state}
         &login_hint={email}

GET /auth/callback?code=...&state=...
  1. Validate code and state params present (400 if not)
  2. Look up OidcPendingLoginEntity[state] (400 if not found or expired)
  3. Delete OidcPendingLoginEntity[state] (one-time use)
  4. POST to {tokenEndpoint}:
       grant_type=authorization_code
       &code={code}
       &client_id={OKTA_CLIENT_ID}
       &client_secret={OKTA_CLIENT_SECRET}
       &redirect_uri={OKTA_REDIRECT_URI}
     → obtain access_token (502 on failure)
  5. GET {userinfoEndpoint} with Authorization: Bearer {access_token}
     → obtain email, name (502 on failure)
  6. sessionToken = UUID.randomUUID()
  7. Create UserSessionEntity[sessionToken] with email, displayName, expiresAt=now+8h
  8. Set-Cookie: SESSION={sessionToken}; HttpOnly; SameSite=Lax; Path=/
  9. Redirect 302 to /
```
